# Wave 8 — Engineer Scorecards, RAG Trends, and Renewal Intelligence Execution Plan

Status: NOT STARTED

## Objective

Deliver balanced engineer scorecards and explainable renewal intelligence using governed targets, fair comparisons, and visible evidence.

## Prerequisites

- Wave 7C is complete.
- Metric owners approve targets, RAG thresholds, eligibility, minimum samples, normalization, and privacy/access rules.
- No individual composite score is allowed unless separately approved through the Wave 0 decision process.

## Workstreams

1. Build scorecards spanning service, quality, effort, reliability, collaboration, and customer evidence as approved.
2. Add RAG status and trends with target version, evaluation window, sample size, exclusions, and evidence.
3. Normalize only where a documented fairness case exists; expose rather than hide material context.
4. Add renewal risk/opportunity signals from coverage, service performance, engagement, entitlement, exceptions, and finance where authorized.
5. Explain each signal, its freshness, contributing evidence, recommended action, and owner.
6. Add review/correction workflow for erroneous data and monitor metric/signal drift.

## Data and API

- Version scorecard definitions and thresholds; do not rewrite prior periods silently.
- Separate descriptive facts, rules-based signals, and any predictive outputs.
- Enforce field-level access for sensitive performance and finance features.
- Record generated-at time and source-data cutoff for every scorecard/signal.

## Verification

- Test threshold boundaries, eligibility, samples, normalization, transfers, leave, late data, and corrections.
- Reconcile every value and renewal signal to evidence.
- Perform fairness, privacy, authorization, accessibility, and realistic-volume performance reviews.
- If predictive models are used, validate calibration, leakage prevention, backtesting, and monitoring.

## Exit criteria

- Scorecards are balanced, reproducible, contextual, and evidence-backed.
- RAG thresholds and renewal signals are versioned and explainable.
- Sensitive data is appropriately restricted and no unapproved composite ranking exists.
- Governance sign-off and all automated/reconciliation reviews pass.

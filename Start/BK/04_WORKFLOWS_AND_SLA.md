# Ticket Workflows, SLA, Assignment, and Escalation

## 1. Workflow Engine

Implement a configurable state-machine service. Store allowed transitions by ticket type and role/permission.

Transition definition includes:

- From status
- To status
- Required permission
- Required fields
- Optional approval
- Whether SLA pauses/resumes
- Notifications to emit
- Automation hooks

Never let the frontend independently decide whether a transition is valid.

## 2. Incident Workflow

```text
New -> Triaged -> Assigned -> In Progress
In Progress -> Pending Client | Pending Internal | Pending Vendor
Pending * -> In Progress
In Progress -> Resolved -> Client Confirmation -> Closed
Resolved/Closed -> Reopened -> Assigned/In Progress
Any active state -> Cancelled/Duplicate with reason and permission
```

## 3. Service Request Workflow

Add optional stages:

- Validation
- Approval
- Fulfillment
- Verification

## 4. Change Workflow

```text
Draft -> Assessment -> Awaiting Approval -> Scheduled -> Implementation
Implementation -> Validation -> Completed -> Closed
Implementation -> Failed/Rolled Back -> Review
```

Required fields include risk, impact, implementation plan, test plan, rollback plan, schedule, owner, and approvals.

## 5. SLA Definitions

Track independently:

- Time to acknowledge
- Time to first response
- Time to assign
- Time to restore/workaround
- Time to resolve
- Time to close
- Update frequency obligation

Each clock has:

- Start event
- Target duration
- Due timestamp
- Pause policy
- Warning thresholds
- Breach timestamp
- Current consumed working time
- Current state

## 6. Working-Time Calculation

Inputs:

- Contract timezone
- Business calendar
- Working periods per weekday
- Holidays
- Exceptions
- Start timestamp
- Target duration
- Pause intervals

Store the calculation version and selected rule IDs so historical results remain explainable after configuration changes.

## 7. SLA Warnings

Suggested thresholds:

- 50% consumed: informational
- 75% consumed: warning
- 90% consumed: urgent escalation
- 100% consumed: breach

Make thresholds configurable per policy.

## 8. Assignment Rules

Evaluation order example:

1. Explicit client/product owner
2. Required product/module skill
3. Active shift/on-call eligibility
4. Queue/team membership
5. Workload threshold
6. Round-robin tie break

Assignments generated by rules must store the rule and reason.

## 9. Escalation Rule Example

```yaml
name: P1 first response escalation
conditions:
  ticket_priority: P1
  status_not_in: [Resolved, Closed, Cancelled]
triggers:
  - at_percent: 50
    actions: [notify_owner, notify_team_leader]
  - at_percent: 75
    actions: [notify_support_manager, require_acknowledgment]
  - at_percent: 100
    actions: [mark_breached, notify_management, create_major_incident_task]
```

Configuration may be stored relationally rather than as YAML; the example shows intent.

## 10. Major Incident Process

For P1/critical incidents:

- Assign incident commander
- Open response timeline
- Set update cadence
- Notify management and agreed contacts
- Track affected clients/sites/services
- Maintain workaround and restoration timestamps
- Create linked problem record after restoration
- Conduct post-incident review
- Publish approved client communication

## 11. Client Communication Rules

- Public reply is visible to authorized client users.
- Internal note is never visible in the portal or outbound client email.
- Email-originated comments must be classified safely.
- Sensitive data detection should warn before posting publicly.
- Templates must remain editable and record the actual sent content.

## 12. Closure Quality

Required resolution fields:

- Resolution category
- Root cause, if known
- Work performed
- Validation performed
- Workaround/permanent fix
- Related knowledge article
- Client confirmation or auto-close reason

## 13. Automation Safety

Automations may assign, notify, tag, set due dates, or propose actions. High-risk actions—contract changes, permission changes, deletion, client-visible closure, or production changes—require explicit authorization and audit.
